### What is the problem with the documentation?
Three gaps found while testing CloudNativePG 1.30.1 failure handling on k3s with local-path storage:

1. **Failover needs the operator, and this is not stated as an operational requirement.** With the operator Deployment scaled to 0, deleting the primary pod caused **no failover and no pod re-creation**. `-rw` had no endpoints for the whole time (101 s outage, until the operator was scaled back to 1; it then failed over in ~11 s). This follows from the design, but failover.md / failure_modes.md should say so explicitly and recommend running the operator with more than one replica, spread across nodes. The default manifest installs 1 replica.

2. **`kubectl cnpg destroy` for an instance on a dead node.** After a node with a local-storage instance was powered off for 10 minutes, `kubectl cnpg destroy cluster-example 3` returned "destroyed", but the pod stayed `Terminating` (the kubelet was unreachable) and the cluster stayed at 2 instances for 5+ minutes. Only after `kubectl delete pod cluster-example-3 --force --grace-period=0` did the operator recreate the instance (healthy 32 s later). The docs for node loss with local storage should include the force-delete step.

3. **Backup plugin as a failover dependency.** No page mentions that an unreachable CNPG-I plugin pod blocks reconciliation, including failover (filed separately as a bug). Until that is changed, the plugin and backup docs should recommend 2+ plugin replicas with anti-affinity.
