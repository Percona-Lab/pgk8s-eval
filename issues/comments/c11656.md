Follow-up from a related test on the same 1.30.1 lab, which is a stricter variant of this report:
- **Host of the primary's node:** the kubelet/agent loses the API server (OUTPUT to the control plane on 6443 dropped). The node goes NotReady after about 45 s.
- **Primary pod (in its netns):** the API server (10.43.0.0/16) is unreachable, and 5432 to and from both replicas is dropped. Port 8000 between pods is left open.

**Result over a 300 s fault:**
- No failover. `currentPrimary` and `targetPrimary` stayed unchanged, and the phase stayed `Cluster in healthy state` throughout.
- The primary logged `Primary lease lost, cannot verify holder, retrying` and was never restarted.
- Sessions opened before the fault kept committing normally: 13,305 acknowledged writes, none lost.
- **New connections through `-rw` failed from +44.9 s until the fault was removed, 264 s in total.**

So there was no split-brain, but the cluster spent the whole fault with a primary that is healthy yet unreachable for new clients, and no failover happened. That matches the 136 s outage in the original report. For comparison, Patroni (Percona Operator 3.1.0) under the same fault demoted the old primary at +10.5 s and promoted a new one at +21.8 s.
