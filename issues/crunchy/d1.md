All three methods moved the data correctly in our tests. But each page leaves out things a real Crunchy cluster depends on, and every gap caused a post-migration problem. Please add a **"What is not migrated, and what changes"** section, linked from every method:

| Item | What happened in the lab | What to tell the reader |
|---|---|---|
| User passwords | Without a pre-created Secret, Percona generated a new password for `hippo` and applied it at promotion. The Crunchy password then failed with `password authentication failed` | Copy each `<cluster>-pguser-<user>` Secret (`password`, `verifier`) to `<percona-cluster>-pguser-<user>` **before** creating the cluster, and list the same users in `spec.users` |
| Built-in extensions | With `cr.yaml` defaults, `pg_stat_statements` and `set_user` were **dropped in all databases**, because disabled built-ins are dropped | Inventory `pg_extension` in every database and enable the matching `spec.extensions.*` before the first start |
| `shared_preload_libraries` / Patroni settings | Crunchy's `dynamicConfiguration` is not carried over; only `pgaudit` was preloaded | Recreate custom parameters in the Percona CR |
| pg_cron | Jobs in the app database stayed in `cron.job` and never ran; Percona forces `cron.database_name=postgres` | Move jobs with `cron.schedule_in_database` from `postgres` |
| Extensions not in Percona images | A plpython3u function failed (`could not access file "plpython3"`). Also not shipped: pg_partman background worker, pg_jobmon, timescaledb, orafce, hypopg, pg_parquet, pgnodemx | Check these in the pre-migration checklist; custom extensions or a custom image |
| Per-user schema | `autoCreateUserSchema` defaults to true, so unqualified `CREATE TABLE` went to schema `hippo` instead of `public` | Set `autoCreateUserSchema: false` to keep Crunchy behaviour |
| Labels and Services | Primary label `role=master` → `role=primary`; Service names follow the new cluster name | Update NetworkPolicies, alerts, scripts and connection strings |
| Monitoring | pgMonitor exporter, `ccp_*` metrics and Grafana dashboards have no equivalent | Plan PMM or a postgres_exporter sidecar |
| pgAdmin, OTel | No equivalents | List them |
| TLS | Standby method keeps Crunchy-issued certificates (see the standby issue) | Replace them after cutover |

Evidence (scripts, logs): https://github.com/Percona-Lab/pgk8s-eval (`crunchy/`, `results/mig*`, `FINDINGS.md`). Tested with Percona Operator 3.1.0 and Crunchy PGO v6.0.3 on k3s.
