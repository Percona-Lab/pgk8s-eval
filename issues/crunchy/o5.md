## Feature request: Crunchy PGO migration assistant

Crunchy Data has announced final planned releases of Crunchy Postgres for Kubernetes 5.6, 5.7, 5.8 and 6.0 around 31 Dec 2026 ([notice](https://info.crunchydata.com/crunchy-postgres-for-kubernetes-notice-of-final-planned-releases)). Percona is the closest replacement, and all three documented methods worked in our lab with Crunchy **v6.0.3**. But each needed manual translation, and every problem we hit came from a step done by hand:

| Manual step | What went wrong when it was missed |
|---|---|
| Copy `<cluster>-pguser-<user>` Secrets | Standby method: Percona generated a new password for `hippo` and applied it at promotion, so the application failed with `password authentication failed` right after cutover |
| Map extensions and `shared_preload_libraries` to `spec.extensions` | `pg_stat_statements` and `set_user` dropped; pg_cron not preloaded (separate issues) |
| Map repo indexes | Crunchy's default `repo1` is a PVC, so its S3 repo is often `repo2`, but `dataSource` must use `repo1` with `repo1-*` keys (k8spg-docs#451) |
| Translate fields | `service`→`expose`, `shutdown`→`pause`, `paused`→`unmanaged`, TLS fields under `secrets.*`, `monitoring`→`pmm`, autoGrow→feature gate |
| Retarget selectors | Primary label `role=master` (Crunchy) becomes `role=primary` (Percona) |
| Schema default | `autoCreateUserSchema` defaults to true, so new unqualified tables go to a per-user schema |

## Proposal
A `kubectl` plugin command (e.g. `kubectl pg migrate-from-crunchy`) or a `PerconaPGMigration` CR that:
1. Reads a Crunchy `PostgresCluster` (**both `v1beta1` and v6 `v1`**) and generates a `PerconaPGCluster`.
2. Runs preflight checks: PG major, architecture, glibc/ICU collation versions, every extension in `pg_extension` across databases against the target image (including C libraries such as plpython3u, pg_partman_bgw, timescaledb), preload list, `cron.database_name`, WAL and tablespace volumes.
3. Copies user Secrets (password + verifier) and optionally the Crunchy CA.
4. Generates the chosen method's runbook (restore / standby / volume), including rollback.

Evidence (scripts, logs, manifests): https://github.com/Percona-Lab/pgk8s-eval (see `crunchy/`, `results/mig*`, `FINDINGS.md`).
