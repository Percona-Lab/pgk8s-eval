## Feature request: parity gaps for Crunchy PGO v6 users

Gaps found while evaluating Percona 3.1.0 as a replacement for Crunchy PGO **v6.0.3**. The Crunchy side was verified in the lab where marked ✓.

| Crunchy v6 | Percona 3.1.0 | Suggested |
|---|---|---|
| Image extensions ✓: `pg_partman` (+ background worker), `pg_jobmon`, `timescaledb`, `orafce`, `plpython3u` (+ hstore/jsonb/ltree transforms), `hypopg`, `passwordpolicy`, `pg_parquet`, `pgnodemx` | Not in the image. A migrated plpython3u function fails: `could not access file "plpython3"` | Ship them in the image or as signed extension bundles |
| PostGIS 3.6 on PG 17/18 | PostGIS 3.5.7 | Bump |
| pgMonitor exporter sidecar (`monitoring.pgmonitor.exporter`, `ccp_*` metrics) + Prometheus/Grafana/Alertmanager stack | PMM only; postgres_exporter as a manual sidecar | Optional exporter with pgMonitor-compatible queries and metric names, so existing dashboards and alerts keep working |
| OpenTelemetry logs/metrics (`instrumentation`) | None (logs via Fluent Bit) | OTel output |
| Standalone `PGAdmin` CRD ✓ (pgAdmin 9.x) | CRD installed, no controller (#1708) | Controller |
| Auto-grow on by default with thresholds | `AutoGrowVolumes` gate off, no thresholds | Parity |
| `volumes.additional` on any container, `volumes.temp` | `extraVolumes` (database container), no temp volume | Parity |
| Logs outside PGDATA by default (`/pgdata/logs/postgres`) ✓, `patroni.logging` | Logs in PGDATA + logcollector; no Patroni logging settings | Parity |
| Service traffic and IP-family policies | Not in `expose` | Add |
| Primary label `role=master` ✓ | `role=primary` | Optional compatibility label for migrated clusters |
| Per-user schema off by default | `autoCreateUserSchema: true` by default | Default false for clusters bootstrapped from `dataSource` or `standby` |

Evidence (scripts, logs, manifests): https://github.com/Percona-Lab/pgk8s-eval (see `crunchy/`, `results/mig*`, `FINDINGS.md`).
