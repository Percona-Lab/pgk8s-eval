Docs version: 3.1.0, page `backups-clone` (restore into a new cluster from object storage). Tested with operator 3.1.0.

When the source cluster stores backups in **repo2** (S3), cloning to a new cluster via `spec.dataSource.pgbackrest` still requires the repo in `dataSource` to be named **`repo1`**. The credentials secret must therefore use `repo1-s3-key` / `repo1-s3-key-secret`, and global options must use `repo1-path` etc. (pointing at the source's repo2 path). The source cluster's own `s3.conf` secret (with `repo2-*` keys) cannot be reused.

Working example (PITR clone, ready in 43 s):
```yaml
spec:
  dataSource:
    pgbackrest:
      stanza: db
      configuration:
      - secret: {name: cluster2-restore-secret}   # contains repo1-s3-key / repo1-s3-key-secret
      global:
        repo1-path: /pgbackrest/postgres-operator/cluster1/repo2   # source cluster's repo2 path
        repo1-s3-uri-style: path
      options: ["--type=time", "--target=\"2026-10-13 22:20:09+00\""]
      repo:
        name: repo1
        s3: {bucket: percona, endpoint: <s3-endpoint>, region: us-east-1}
```
Please document this naming rule, with an example where the source repo is not repo1.
